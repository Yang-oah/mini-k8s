# G1 本地启动与使用

本文描述最小控制面的启动方式。G1 曾在真实 API 和 etcd 上通过验收，具体代码版本和证据见 [G1 验收记录](../artifacts/acceptance/20261103-214005-98cdf2db/G1.md)。后续修改共用 API 或模型时，须重跑受影响的检查；命令示例和单元测试本身不代表当前版本已经通过。G2 正在实施，真实运行时、多节点调度和 Service 转发尚未完成。

## 依赖与隔离

- Go 1.23.0 或兼容版本；模块版本以仓库 `go.mod`、`go.sum` 为准。直接使用的 etcd Go 客户端版本为 **3.5.21**，YAML 解析库为 **3.0.1**。
- 单成员 etcd **3.5.21**；本例还使用 OpenSSL 和 Python 3 生成临时证书与身份文件。以下示例面向 Linux，在仓库根目录运行。
- 测试目录包含私钥、令牌和 etcd 数据，不要提交到仓库，也不要发送给他人。证书、令牌与数据仅用于本地测试。

当前 API 到 etcd 的连接没有配置客户端证书或 CA 的选项，以下示例将 etcd 绑定到本机回环地址。不要把未经保护的 etcd 端口暴露到网络；如需跨主机部署，须先补齐安全传输与访问控制。

## 创建本地 TLS 和身份文件

下面的命令创建一次性测试 CA、包含 `127.0.0.1` 和 `localhost` 的服务端证书，并分别生成独立令牌。所有文件保存在临时目录中，权限由 `umask 077` 限制。

```sh
umask 077
export MINI_K8S_DIR="$(mktemp -d)"

openssl req -x509 -newkey rsa:3072 -nodes -days 1 \
  -keyout "$MINI_K8S_DIR/ca.key" -out "$MINI_K8S_DIR/ca.pem" \
  -subj '/CN=mini-k8s local CA' \
  -addext 'basicConstraints=critical,CA:TRUE' \
  -addext 'keyUsage=critical,keyCertSign,cRLSign'
openssl req -new -newkey rsa:3072 -nodes \
  -keyout "$MINI_K8S_DIR/server.key" -out "$MINI_K8S_DIR/server.csr" \
  -subj '/CN=localhost'
printf '%s\n' 'subjectAltName=IP:127.0.0.1,DNS:localhost' 'extendedKeyUsage=serverAuth' > "$MINI_K8S_DIR/server.ext"
openssl x509 -req -in "$MINI_K8S_DIR/server.csr" \
  -CA "$MINI_K8S_DIR/ca.pem" -CAkey "$MINI_K8S_DIR/ca.key" -CAcreateserial \
  -out "$MINI_K8S_DIR/server.pem" -days 1 -extfile "$MINI_K8S_DIR/server.ext"

python3 - <<'PY'
import json, os, pathlib, secrets
directory = pathlib.Path(os.environ['MINI_K8S_DIR'])
tokens = {name: secrets.token_hex(32) for name in ('admin', 'scheduler', 'controller', 'agent')}
for name, value in tokens.items():
    (directory / (name + '.token')).write_text(value + '\n', encoding='utf-8')
auth = {
    'admin': tokens['admin'],
    'scheduler': tokens['scheduler'],
    'controller': tokens['controller'],
    'agents': {'node-a': tokens['agent']},
}
(directory / 'auth.json').write_text(json.dumps(auth), encoding='utf-8')
PY
```

身份配置格式为 `{"admin":"…","scheduler":"…","controller":"…","agents":{"节点名":"…"}}`。`admin` 和 `scheduler` 必填，各身份的令牌不得相同；Agent 令牌与节点名绑定。管理资源使用管理员令牌，status 使用相应 Agent 身份，bind 使用 scheduler 身份。不要在命令参数、示例日志或源码中直接写入令牌。

## 启动 etcd 和 API

在同一 shell 中继续；请先确保本机 2379、2380 和 8443 端口未被其他服务占用。下面的后台进程只用于本地测试。

```sh
etcd --version
etcd --data-dir "$MINI_K8S_DIR/etcd" \
  --listen-client-urls http://127.0.0.1:2379 \
  --advertise-client-urls http://127.0.0.1:2379 \
  > "$MINI_K8S_DIR/etcd.log" 2>&1 &
ETCD_PID=$!

go build -o "$MINI_K8S_DIR/mini-api" ./cmd/mini-api
go build -o "$MINI_K8S_DIR/mini-k8s" ./cmd/mini-k8s
"$MINI_K8S_DIR/mini-api" \
  -listen 127.0.0.1:8443 -etcd http://127.0.0.1:2379 \
  -tls-cert "$MINI_K8S_DIR/server.pem" -tls-key "$MINI_K8S_DIR/server.key" \
  -auth-file "$MINI_K8S_DIR/auth.json" \
  > "$MINI_K8S_DIR/api.log" 2>&1 &
API_PID=$!
```

etcd 首次启动和 API 监听需要时间；请求失败时先查看这两个日志并确认进程仍在运行。API 只监听 HTTPS；CLI 校验服务端证书，不提供跳过校验的选项。证书中的名称必须与 `--server` 使用的名称或 IP 匹配。

## 操作示例

连接参数必须放在子命令之前。以下 YAML 采用 `cpuMilli`（毫核）和 `memoryBytes`（字节）；示例镜像占位符用于模型操作，真实运行前必须替换为测试节点可获取的固定镜像。G1 不启动容器。

```sh
"$MINI_K8S_DIR/mini-k8s" --server https://127.0.0.1:8443 \
  --ca-file "$MINI_K8S_DIR/ca.pem" --token-file "$MINI_K8S_DIR/admin.token" \
  apply -f examples/g1-pod.yaml
"$MINI_K8S_DIR/mini-k8s" --server https://127.0.0.1:8443 \
  --ca-file "$MINI_K8S_DIR/ca.pem" --token-file "$MINI_K8S_DIR/admin.token" \
  apply -f examples/g1-replicaset.yaml
"$MINI_K8S_DIR/mini-k8s" --server https://127.0.0.1:8443 \
  --ca-file "$MINI_K8S_DIR/ca.pem" --token-file "$MINI_K8S_DIR/admin.token" \
  get pods
"$MINI_K8S_DIR/mini-k8s" --server https://127.0.0.1:8443 \
  --ca-file "$MINI_K8S_DIR/ca.pem" --token-file "$MINI_K8S_DIR/admin.token" \
  scale rs example-rs --replicas 3
"$MINI_K8S_DIR/mini-k8s" --server https://127.0.0.1:8443 \
  --ca-file "$MINI_K8S_DIR/ca.pem" --token-file "$MINI_K8S_DIR/admin.token" \
  get rs example-rs
"$MINI_K8S_DIR/mini-k8s" --server https://127.0.0.1:8443 \
  --ca-file "$MINI_K8S_DIR/ca.pem" --token-file "$MINI_K8S_DIR/admin.token" \
  delete -f examples/g1-replicaset.yaml
"$MINI_K8S_DIR/mini-k8s" --server https://127.0.0.1:8443 \
  --ca-file "$MINI_K8S_DIR/ca.pem" --token-file "$MINI_K8S_DIR/admin.token" \
  delete -f examples/g1-pod.yaml
```

`apply` 对已有对象读取当前版本再更新；冲突返回错误，需要重新读取后重试。Pod spec 不可原地修改。多文档文件不保证跨对象事务，失败前成功提交的对象会逐项打印。`get` 返回 JSON。删除未绑定对象后，应通过 `get` 核实清理情况。

## 检查和停止

代码检查可运行 `gofmt` 检查、`go vet ./...`、`go test ./...` 和 `go build ./...`。正式 G1 还必须执行 Gateway 的 G1-01 至 G1-06，记录每项结果、环境、源码版本、日志与清理证据；不得以模拟测试代替真实 etcd/API 验收。

完成本地测试并确认无需保留现场后，可在启动进程的同一个 shell 停止它们：

```sh
kill "$API_PID" "$ETCD_PID"
wait "$API_PID" "$ETCD_PID" 2>/dev/null || true
```

临时目录中仍有私钥、令牌和数据，按本机安全策略处理；排障证据需先脱敏。此项目是受限 demo，不提供生产级高可用、租户隔离或完整 PRD 故障恢复保证。
