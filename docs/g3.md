# G3 单节点 Agent 与运行时

G3 将已绑定 Pod 的期望状态交给本机 Agent，并通过 containerd 的 CRI v1 接口创建、认领和清理实例。该阶段使用受限测试客户端绑定 Pod；自动调度和双节点网络属于 G4。

## 环境前提

- Linux Worker 上的 containerd 已启用 CRI v1；Agent 必须能够访问本机 Unix socket。
- containerd 使用可用的 CNI 配置，bridge、host-local 等插件已安装；Pod 网段与宿主机及其他网段不重叠。
- 验收机需要 Go、etcd 和 `crictl`，并预拉取固定 SHA-256 digest 的测试镜像。测试镜像需包含 `sh`、`sleep`，且 shell 支持变量赋值、拼接和循环。
- 测试运行时需要足以操作 CRI 和 CNI 的本机权限。不要将 CRI socket 暴露到网络；凭据和 Agent 状态目录必须受保护。

## Agent 参数

构建 `cmd/mini-agent` 后，使用已预注册节点的名称、该节点独立令牌和 API CA 启动。主要参数如下：

| 参数 | 用途 |
| --- | --- |
| `-server`、`-ca-file` | API 的 HTTPS 地址和可信 CA。 |
| `-node`、`-token-file` | 预注册节点名称和节点身份凭据。 |
| `-cri-endpoint` | 本机 containerd CRI Unix socket，默认 `unix:///run/containerd/containerd.sock`。 |
| `-state-dir`、`-log-dir` | 本机互斥锁、创建意图及容器日志目录。 |
| `-resync` | 周期性读取分配和对账的间隔。 |

同一节点只能有一个 Agent 持有运行时锁。Agent 重启时按 Pod UID 检查已有实例，不能只凭名称认领或删除容器；如果创建结果无法确认，会保守等待，而不是盲目重复创建。

## 本机日志与迟到清理

运行中的 Agent 在状态目录内提供权限受限的本机控制 socket。可通过 `mini-agent -state-dir <目录> -logs-uid <Pod UID> -tail 100` 读取对应容器的日志。

清理被删除或重建 Pod 遗留的旧 UID 时，可通过 `mini-agent -state-dir <目录> -cleanup-name <名称> -cleanup-uid <旧 UID>` 请求正在运行的 Agent 核对后清理。该操作需要先核实实际情况；Agent 会重新查询 API、核对本节点分配和运行时身份，再决定是否执行。

## 验收

按 [Gateway.md](../Gateway.md) 执行 G3-01 至 G3-05，记录实际 CRI sandbox、容器、日志、资源限制和清理证据。Linux 验收入口为 `scripts/acceptance/g3.sh`；运行前需设置 `G3_TEST_IMAGE` 为已预拉取的镜像 digest、`G3_CNI_NETWORK` 为实际 host-local 网络名，并通过 `G3_POD_CIDR` 指定与该 CNI 配置一致的 IPv4 网段。脚本先验证当前版本的 G1/G2 前置条件；缺少权限或环境时应报告 BLOCKED。

例如，在 Go 位于 `/usr/local/go/bin`、etcd 位于 `/usr/local/bin`，并已确认测试网络和镜像可用时，可在仓库根目录执行：

```sh
sudo env PATH=/usr/local/go/bin:/usr/local/bin:/usr/bin:/bin \
  G3_TEST_IMAGE='<已预拉取的镜像@sha256:digest>' \
  G3_CNI_NETWORK='<实际 host-local 网络名>' \
  G3_POD_CIDR='<实际 Pod IPv4 网段，例如 10.88.0.0/24>' \
  G3_CONTAINERD_CONFIG='/etc/containerd/config.toml' \
  bash scripts/acceptance/g3.sh
```

按测试机的实际安装位置调整 PATH，并确保这些目录由可信管理员维护。containerd 2.x 若未在 CRI 信息中提供 `sandboxImage`，需通过 `G3_CONTAINERD_CONFIG` 指定目标 daemon 实际使用的绝对配置路径；确认该配置已由正在运行的 daemon 加载。运行用户需要能够获取 Go 模块或已准备好模块缓存；containerd 所需的 sandbox 镜像也应事先就绪。脚本输出的证据目录包含各项检查、版本、状态和清理结果。

G3 的单元测试或交叉编译不能代替真实 Linux/containerd/CNI 验收。G3 未完成前，不进入 G4。
