## 仅补测 G5-07

1. 在与最终验收关联的同一源码版本和两节点环境，创建一组专用于清理测试、可按 UID 识别的 RS、Pod 和 Service，记录其 UID、地址、节点、创建与删除操作；不要使用无关负载。两侧在创建前分别采集 CNI 租约、CRI 清单和相关规则基线，并保存节点预留及 API 对象。
2. 按 [Service 验收说明](g5-service.md#节点只读取证辅助脚本)先在两侧启动只读采集器；两边必须使用 `--iptables full`，各自出现 `READY` 文件并核对该文件所指样本之后，才能进行删除。使用两台节点各自的 CNI 目录、CRI socket 和可信 `crictl`，记录两侧时钟偏差。`READY` 仅表明当时的必要采样成功，不证明基线正确、之后采样成功或整个 Gate 通过。采样周期加各命令耗时可能超过一秒，因此须查看每项真实采样时间与退出码，不以配置的 interval 代替时间证据。
3. 删除本轮 RS/Service，记录各删除请求成功的时间。持续观察两侧 CRI、Node reserved、API 对象、租约及规则；相应终态采样的开始时间不得早于对应删除请求成功，完成时间须不晚于 30 秒窗口末尾，并考虑节点间时钟误差。规则比较需确认本轮 Service 规则消失、无关规则未被更改；包计数变化需与规则结构变化区分。保留采样原件和基线，失败时不要用事后样本冒充窗口内结果。
4. 核对地址口径：Pod 的 host-local 租约和节点预留应回到测试前基线，已删除 Service 的转发规则应消失。ClusterIP 声明按 [Gateway G5-07](../Gateway.md#7-g5service-与整体-demo) 的已知限制永久保留，不要求地址池可用数回到测试前。报告须分开列出 Pod 租约、`active` 地址和 `retained` 声明，不能把 `retained` 写成已释放。

本次补测只覆盖 G5-07，不替换 G5c 其他场景的结果。跨轮引用须保持同一最终代码版本，并分别记录环境、操作、时间和证据，不能拼接成一次未发生过的连续时间窗口。最终还需关联同版本 G1–G4、安装/示例/排障说明的执行结果，按 Gateway 汇总 G5-01–07；缺失的检查保持未完成。
