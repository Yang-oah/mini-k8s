# G2 副本控制器

G2 在 G1 控制面的基础上实现 ReplicaSet 对账。它只验证资源模型和副本决策：此阶段的节点和 Pod 状态由测试客户端模拟，不代表容器运行时或网络已经通过验证。

## 启动

先按 [G1 操作说明](g1.md) 启动 etcd 和 API，并在身份配置中设置独立的 `controller` 令牌。在相同 shell 中继续：

```sh
go build -o "$MINI_K8S_DIR/mini-manager" ./cmd/mini-manager
"$MINI_K8S_DIR/mini-manager" \
  -server https://127.0.0.1:8443 \
  -ca-file "$MINI_K8S_DIR/ca.pem" \
  -token-file "$MINI_K8S_DIR/controller.token" \
  -resync 2s > "$MINI_K8S_DIR/manager.log" 2>&1 &
MANAGER_PID=$!
```

只运行一个 manager 实例。设置好 [G1 示例中的 CLI 参数](g1.md#操作示例)后，创建 ReplicaSet、查看 Pod、修改副本数并观察收敛；停止测试时执行 `kill "$MANAGER_PID"`，并等待该进程退出。

## 对账约束

- 控制器按 ReplicaSet 的 UID 识别子 Pod，不认领仅标签相同的独立 Pod。
- 已绑定但尚未确认停止的 Pod，即使处于删除中或 Unknown 状态，仍占副本额度。
- 创建响应丢失时先用同一名称查询并确认，不能通过换名重试绕过未知结果。
- 删除中的 ReplicaSet 不再补建；已有子 Pod 必须完成回收后才能最终删除所属对象。
- Watch 用于及时触发对账，周期性重新读取则用于修复断线和遗漏；API 写入冲突需要重新读取。

## 验收

G2 必须先有 G1 通过记录，再按 [Gateway.md](../Gateway.md) 执行 G2-01 至 G2-06。需使用真实 API 和 etcd，保留每项结果和测试资源清理证据。提交对共用 API 的修改后，也要重跑受影响的 G1 检查。
