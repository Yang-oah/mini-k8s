R1 已合并到 `master`（`77f47f1`）。R2 按下面的顺序拆分。每步保留独立的验收记录，再进入依赖它的下一步。

| 步骤 | 实现 | 验收 |
| --- | --- | --- |
| R2-A1 | API 普通请求、Watch 和节点恢复请求各自设在途预算；为 Watch 写出设期限 | 填满任一预算只影响对应请求类型。超限请求返回 429，取消、结束或写失败后释放名额。节点状态与 Pod 清理在普通请求过载时仍可进入 |
| R2-A2 | 测量并约束 API Server 对 etcd 的在途 RPC，区分普通事务与恢复路径 | 隔离 etcd 实测上下限及故障恢复。超时仍按 R1 的操作身份确认结果，不能重复写入 |
| R2-B | 按 RS UID 去重入队，每个 UID 串行，不同 UID 可并行；队列溢出触发重新对账 | 同一 UID 无并行对账，队列与工作数有界。负载下降后最终状态收敛 |
| R2-C | Controller 以一致 List 建立索引，再从该 revision 接续 Watch | 覆盖同 revision 多事件、断线、压缩和重建；缓存不可信时暂停依赖缓存的写决策 |

## R2-A1 的行为

- 在 mini-api 提供可配置的三类预算。无效配置启动失败。过载在进入业务处理前返回 429 和可识别错误，避免在应用内部排队。
- 恢复预算用于 Agent 读取本节点、读取 Pod 列表或单项，以及上报本节点状态和确认 Pod 清理。真实 Agent 必须先读版本和对象身份才能写入。Watch 仍使用独立预算，既有身份和归属校验继续执行。
- 普通存储请求沿用原期限。有请求体的已接纳请求使用 10 秒读取期限。HTTP/1 请求带请求体且超限时关闭连接，避免响应前等待未读完的请求体。
- Watch 写入和 flush 使用每次输出的期限。输出失败则结束 Watch，客户端沿用重新 List 的恢复流程。空闲 Watch 不因没有事件而超时。连接数预算不等同于 etcd RPC 并发上限。
- 保留既有事务、授权和一致性检查。R1 操作身份和超时语义沿用。缓存、队列、节点会话和独立运维告警分别在后续步骤交付。

| mini-api 参数 | 默认值 | 作用 |
| --- | ---: | --- |
| `-max-inflight` | 64 | 已认证普通 API 请求的在途上限 |
| `-max-watches` | 32 | 资源集合 Watch 的连接上限 |
| `-max-recovery-inflight` | 16 | Agent 心跳和清理所需的读取及写入上限 |
| `-watch-write-timeout` | 2s | 单次 Watch 写入及 flush 的期限 |

预算按 API 进程计算。上限是部署配置，初始值需结合运行规模验证。Pod 清理的所属节点仍由原事务校验。
